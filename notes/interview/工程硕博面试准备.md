## 1. 计算机性能评价

### 1. **CPU 执行时间公式**

\(T = I\times CPI\times T_{clock}\) I：指令数；CPI：每条指令平均时钟周期数；\(T_{clock}\)：时钟周期。 主频 = \(1/T_{clock}\)；**主频高 ≠ 一定更快**，还要看 CPI 与指令数。 2. **Amdahl 定律（阿姆达尔定律，高频！）** 加速比 = \(\frac{1}{(1-F_e)+F_e/S_e}\) \(F_e\)：可加速部分占总执行时间比例；\(S_e\)：可加速部分提升倍数。 核心：系统加速上限由**不可加速部分**决定。常用于并行 / 硬件加速评估（大模型并行加速一定会关联这个）。 3. 基准测试集（Benchmark）：评价计算机性能，避免只看主频。

### 2. 指令集体系结构 ISA

1. **CISC（复杂指令集，x86）**：指令长度不等，指令多，可直接操作内存；硬件复杂。
2. **RISC（精简指令集，ARM/RISC-V）**：定长指令、指令简单，Load/Store 架构：**只有 load、store 可以访问内存，运算指令只操作寄存器**；流水线更容易做，现代 GPU/NPU 基本基于 RISC 思想。

> Load-Store 架构：运算单元和内存解耦，减少访存，提升流水线效率。

### 3. 存储层次与局部性原理【重中之重】

### 局部性原理（存储层次的理论基础）

- **时间局部性**：刚访问的数据，短期内会再次访问（循环变量）
- **空间局部性**：访问某个地址，相邻地址大概率很快被访问（数组顺序遍历）

### 存储层级（从上到下）

寄存器 → L1 Cache → L2 Cache → L3 Cache → 主存 DRAM → SSD/HDD

- 上层：速度快、容量小、单位成本高；下层相反。
- **存储墙 Memory Wall**：处理器算力增长速度远高于内存带宽 / 延迟提升速度。CPU/GPU 大量时间等待数据搬运，而不是计算。**程老师课题组核心研究痛点，面试必准备**。

### 4. Cache 高速缓存

Cache 保存主存块的最近访问副本，减少访问主存次数。

#### 4.1 三种映射方式

1. **直接映射**：主存块号 mod Cache 行数，只能固定放到对应行。优点硬件简单；缺点冲突缺失严重。
2. **全相联**：主存块可以放在 Cache 任意行。冲突缺失最少；但查找代价高、硬件昂贵。
3. **组相联（主流，如 4 路 / 8 路组相联）**：Cache 划分为组；块只能放入对应组内任意一行。平衡硬件开销和缺失率，现代 CPU/GPU 都用。

#### 4.2 Cache 缺失的三类

1. **强制缺失（冷缺失）**：第一次访问，Cache 无副本
2. **容量缺失**：工作集大于 Cache 容量，放不下
3. **冲突缺失**：多个块竞争同一组 / 同一行位置（组相联 / 直接映射特有）

#### 4.3 替换策略

Cache 满了要淘汰旧块：LRU（最近最少使用，最常用）、FIFO、Random。 LRU 优点：契合局部性；缺点：硬件实现开销更大。

#### 4.4 Cache 一致性（多核）

多核 CPU 每个核有私有 L1/L2 Cache，同一数据存在多副本。修改后要保证所有核看到一致值。 经典协议 **MESI**：Modified、Exclusive、Shared、Invalid。

- M：本核修改，与主存不一致；其他核副本失效
- E：独有，未修改
- S：多核共享，和主存一致
- I：无效

> 追问场景：多 GPU 训练时，GPU 之间的一致性和 CPU 多核 Cache 一致性不一样，GPU 一般不维持全局硬件 Cache 一致性，靠软件保证。

### 5. 指令流水线 Pipeline

将一条指令拆分成多个阶段（取指 IF、译码 ID、执行 EX、访存 MEM、写回 WB），多条指令**重叠并行执行**。

> 重点：流水线提升**吞吐率**，**不会减少单条指令的执行延迟**。

### 流水线三大冒险（Hazard）

1. **结构冒险**：多条指令同一周期争抢同一硬件资源。解决：复制硬件资源。
2. **数据冒险**：指令之间存在数据依赖，后面指令需要前面指令的结果。
    - 解决：旁路转发 Forwarding；无法转发时插入气泡 bubble。
    - 依赖分类：RAW 写后读（最常见）、WAR 读后写、WAW 写后写（乱序流水线才会出现）
3. **控制冒险**：分支指令，下一条 PC 地址不确定。解决：**分支预测**（静态预测、动态预测）。

#### 补充：乱序执行（Out-of-Order）

CPU 不严格按程序顺序执行指令，只要操作数就绪就可以执行，掩盖延迟、提升流水线利用率；会引入 WAR、WAW 依赖，需要重排序缓存 ROB。

### 6. 内存系统：DRAM、异构内存

1. **DRAM**：主存，电容存储，需要定期刷新；位单元简单、容量大、带宽低于 SRAM。SRAM 用于 Cache，速度快、面积大、成本高。
2. **异构内存系统**：同一系统包含多种内存介质（高速 HBM、普通 DRAM、持久内存），统一地址空间。
    - HBM 高带宽显存：GPU 使用，堆叠，带宽极高，但容量有限、价格贵。
    - 核心思路：冷热数据分离。热数据放高速 HBM，冷数据迁移到大容量低速内存。**程老师课题组重点方向**。

### 7. 异构计算 Heterogeneous Computing

系统集成多种不同架构计算单元协同完成任务：CPU + GPU + NPU/TPU。

- CPU：复杂控制、分支、操作系统调度，串行逻辑强，并行度低
- GPU：SIMT 单指令多线程，大量轻量计算核心，擅长稠密矩阵运算；分支处理弱
- NPU/TPU：面向矩阵 / 向量运算做硬件定制，专门加速 AI 算子

异构计算带来的问题：**跨设备数据传输开销**，设备间通信带宽经常成为瓶颈。

### 8. 存算一体 In-Memory Computing（重点！程老师方向）

冯诺依曼瓶颈：计算单元和存储分离，大量时间消耗在数据在内存与 ALU 之间搬运，计算本身耗时反而小。 存算一体：**在存储阵列内部直接完成计算**，消除数据来回搬运。

- 类型：SRAM 存算一体、DRAM 存算一体、非易失存算一体 ReRAM 等
- 优势：大幅降低访存延迟、功耗，适合 AI 推理矩阵向量乘法
- 缺点：计算精度受限、器件噪声、编程模型难、误差管理复杂；属于前沿研究

### 9. 向量架构 & SIMD/SIMT

- SIMD（单指令多数据）：一条指令，多个 ALU 对多组不同数据执行同样操作；CPU 的 AVX、SSE。
- SIMT（单指令多线程）：GPU 采用。单条指令调度大量线程，线程可以有独立 PC，允许分支。同一 warp 内线程分支会带来分支分歧，性能下降。

### 10. 多处理器与并行基础

1. 并行分类：指令级并行 ILP（流水线、乱序）；数据级并行 DLP（SIMD/SIMT）；任务级并行 TLP（多核、多机）
2. 多核：单芯片多个处理器核，共享 L3 Cache 或共享内存。
3. 并行系统内存模型：**UMA 统一内存访问**（所有核访问内存延迟一致）；**NUMA 非一致内存访问**，不同节点访问内存延迟不同，多路服务器常用，访存位置会显著影响性能。

### 11. 与大模型结合的面试拓展提问点（很容易被追问）

1. 为什么大模型训练推理是访存瓶颈而不是计算瓶颈？ 大模型参数巨大，算子计算强度不高，反复读写显存，带宽受限，就是存储墙。
2. HBM 为什么适合 GPU 大模型训练？高带宽，但容量有限。
3. 异构内存如何缓解大模型显存不足：冷热参数 / 激活分离，冷数据挪到主机内存。
4. 存算一体为什么适合 AI 推理：推理多为矩阵向量乘，访存密集，存内计算减少搬运。

## OS
### 1. 操作系统核心定位

OS 是硬件与应用之间的系统软件，核心职能：**资源管理（CPU、内存、IO）、抽象硬件、隔离、并发控制**。 四大管理模块：进程管理、内存管理、IO 管理、文件系统。

### 2. 进程与线程（必考点）

#### 进程

**资源分配的最小单位**。

- 独立虚拟地址空间、独立堆、文件描述符、信号上下文
- 进程切换：需要切换页表、刷新 TLB；开销**很大**
- 进程间天然隔离；一个进程崩溃，一般不影响其他进程
- 进程通信 IPC：管道、消息队列、共享内存、Socket。共享内存速度最快，但需要用户自己做同步。

#### 线程

**CPU 调度的最小单位**，隶属于进程。

- 同一进程内所有线程**共享进程的虚拟地址空间、全局变量、文件句柄**
- 线程私有：栈、寄存器、程序计数器 PC
- 线程切换：只切换寄存器，**不需要更换页表**，开销远小于进程切换
- 缺点：一个线程崩溃，整个进程直接崩溃；共享变量极易产生竞态条件

### 对比总结口述版

进程是资源容器，线程是执行流。进程隔离强、切换贵；线程共享地址空间、切换轻量，但共享数据带来并发安全问题。

#### 协程（补充，容易追问）

用户态轻量级执行流，由用户程序调度，不经过 OS 内核；切换开销比线程更小。很多深度学习框架底层会用到。

### 3. 并发、竞态条件、同步互斥

**竞态条件 (Race Condition)**：多个执行流同时读写**共享可变数据**，最终结果取决于调度时序，结果不可预测。 出现竞态的三要素：共享变量、并发访问、至少一个是写操作。

#### 同步原语

1. **互斥锁 mutex**：保证同一时刻，临界区只能有一个线程进入，用于互斥。
2. **信号量 semaphore**：通用计数器。值 = 1 等价互斥锁；大于 1 可控制资源并发数量，实现同步 / 互斥。
3. **条件变量 condition variable**：必须搭配 mutex。线程等待某个条件成立；其他线程修改条件后发信号唤醒等待线程。

> 典型场景：生产者 - 消费者模型。

#### 死锁

**死锁四个必要条件，必须同时满足才会死锁**

1. 互斥：资源独占
2. 持有并等待：线程拿到部分资源，再申请新资源，不释放已有资源
3. 不可剥夺：资源不能被强制抢走
4. 循环等待：多个线程形成资源申请环 破坏任意一条，就可以解除死锁。 处理策略：死锁预防、死锁避免（银行家算法）、死锁检测 + 恢复。

### 4. 内存管理（重中之重，和体系结构、大模型强关联）

### 虚拟内存 Virtual Memory

给每个进程提供**独立、连续的虚拟地址空间**，屏蔽物理内存真实布局，实现：

1. 进程间内存隔离
2. 内存抽象，程序不用关心物理地址
3. 内存过载：程序总内存可以大于物理内存，把冷页面换入外存

分页机制：

- 虚拟地址 = 虚拟页号 + 页内偏移
- 物理地址 = 物理页框号 + 页内偏移
- 页大小固定；偏移位数固定，不需要翻译

**缺页中断 Page Fault** 访问虚拟页，但页面不在物理内存 → 触发中断，OS 从磁盘读取页面载入内存；若物理内存满，执行页面置换。

页面置换算法（内存不够时，淘汰哪一页）

- LRU：淘汰最近最少使用。符合局部性，性能好；硬件实现复杂
- FIFO：先进先出，简单；会出现 Belady 异常（内存增大，缺页次数反而上升）
- Clock（时钟算法）：LRU 的低成本近似，工程最常用

#### 页表 & TLB

**页表**：存储「虚拟页号 → 物理页框号」映射，保存在内存。

- 单级页表：简单，但地址空间大时，页表本身占用内存巨大
- **多级页表**：只给用到的虚拟地址分配页表项，节省内存空间；地址翻译需要多次访存。

**TLB（快表 Translation Lookaside Buffer）** MMU 内部的高速 Cache，缓存常用页表项，加速地址翻译。

- TLB 命中：直接拿到物理地址，一次访存
- TLB 缺失：去内存访问页表，延迟显著增加

> 面试延伸：大模型工作集巨大，容易造成 TLB 抖动，带来额外访存开销。

#### 内存分段（了解即可，提问概率低）

段是逻辑单元（代码段、数据段），段长可变；现代 OS 以分页为主。

### 5. CPU 调度

调度目标：公平、吞吐高、响应时间短、减少饥饿。

- 抢占式调度：高优先级任务可以打断正在运行的任务（现代 OS 主流，Linux）
- 非抢占式：任务主动放弃 CPU

基础调度算法：FCFS、短作业优先 SJF、时间片轮转 RR。 Linux：CFS 完全公平调度器，基于虚拟运行时间。

### 6. I/O 管理

磁盘是块设备，最大瓶颈是**寻道时间**（磁头移动），大于旋转延迟，远大于数据传输时间。 磁盘 IO 调度算法，目标减少磁头移动距离：

1. FCFS 先来先服务：简单，寻道开销大
2. SSTF 最短寻道优先：优先访问离磁头最近；容易饥饿
3. SCAN 电梯算法：单向扫到磁盘尽头再反向；避免饥饿；工程最常用

IO 控制方式：

1. 轮询：CPU 不断查询设备状态，CPU 浪费大
2. 中断：设备完成后发中断通知 CPU，CPU 平时可以做别的任务
3. DMA 直接内存访问：硬件直接在内存和设备之间搬运数据，**不占用 CPU**；大文件、GPU 数据传输广泛使用。

### 7. 文件系统（简单了解，考得少）

核心：把磁盘块抽象成文件，目录是索引。 inode：保存文件元信息（大小、权限、磁盘块指针），不存文件名；文件名存在目录项。

### 8. 面向面试拓展（和你的方向关联，很容易被追问）

1. 虚拟内存对大模型训练的意义：可利用 swap / 异构内存，把冷参数、激活值放到主机内存，缓解 GPU 显存不足。
2. TLB 抖动：当访问的页面集合超出 TLB 容量，每次地址翻译都 TLB miss，性能暴跌。超大内存负载下会出现。
3. 多线程训练框架（PyTorch）里的竞态：梯度更新如果不加锁会出现错误，框架会用原子操作 / 分布式通信机制处理。
4. DMA：GPU 和主机之间数据传输依靠 DMA，减少 CPU 开销。

## 分布式系统
### 1. 分布式系统基础概念

**分布式系统**：由多台独立计算机，通过网络互联，对外呈现为一个统一整体。 核心痛点：**网络不可靠、网络延迟、节点故障、时钟不同步**。

- 节点：独立服务器 / 计算设备（可以是 GPU 服务器）
- 网络分区：部分节点之间网络断开，消息丢失 / 延迟，是分布式系统无法完全避免的故障。
- 故障类型：节点宕机、网络丢包、消息延迟、消息重复、消息乱序。

> 单机系统：内存、CPU 都在一台机器；分布式系统难点不在计算，而在**处理故障与维护状态一致性**。

### 2. CAP 理论【必考】

三个属性：

- **C 一致性 Consistency**：任意节点读到的数据是相同的。写完成后，任何客户端读取都能拿到最新写入结果（强一致）。
- **A 可用性 Availability**：客户端每一个请求，都能收到非失败的响应（不一定是最新数据）。
- **P 分区容错 Partition Tolerance**：发生网络分区时，系统仍然可以继续工作。

核心结论： **在分布式系统中，网络分区 P 一定会发生，无法避免。因此系统只能在 C 和 A 之间做取舍。**

- CP：牺牲可用性，保证强一致性。分区发生时拒绝服务。代表：ZooKeeper。
- AP：牺牲强一致性，保证可用。只能保证**最终一致性**，一段时间后各节点数据自动同步。代表：Cassandra。

补充：CAP 不是 “三选二” 静态选择，是**分区发生时的取舍策略**；无分区时，可以同时满足 C 与 A。

### 3. BASE 理论（CAP 的工程落地，面试常追问）

- **Basically Available 基本可用**：故障时系统仍可用，可能性能下降，部分功能降级。
- **Soft state 软状态**：节点状态可以不实时一致，允许中间状态。
- **Eventually consistent 最终一致性**：一段时间后，没有新写入，所有节点数据最终达成一致。 互联网大规模存储系统大多采用 BASE，牺牲强一致换取高可用。

### 4. 一致性模型（区分强弱一致）

1. **强一致性**：写操作返回成功后，所有客户端读取到最新数据。代价高，延迟大。
2. **最终一致性**：短时间内读到旧数据，无新写入后，最终全部同步。工程最常用。
3. 因果一致性：有因果关系的读写，保证顺序；无因果的可以不一致。

### 5. 分布式共识协议（重点掌握 Raft，Paxos 了解即可）

共识问题：多个节点，在存在故障 / 丢包的情况下，对同一个值达成一致决策。

### Raft（优先背诵，面试首选）

节点角色：

1. Leader 领导者：接收客户端请求，负责日志复制，向 Follower 同步日志。整个系统同一时刻最多 1 个 Leader。
2. Follower 跟随者：被动接收 Leader 日志，不主动发起请求。
3. Candidate 候选者：Leader 失联时，Follower 转变为 Candidate，发起选举投票。

工作流程：

1. 选举：Leader 定期发送心跳。Follower 收不到心跳，升级 Candidate，发起投票，获得多数票则成为新 Leader。
2. 日志复制：客户端写请求发给 Leader；Leader 追加日志条目，并行复制给所有 Follower；**多数节点复制成功后，日志提交生效**，再回复客户端成功。
3. 安全性保证：只有已经提交的日志，才会被节点执行；不会出现日志冲突覆盖。

特点：易理解，工程实现广泛。ZooKeeper 底层 ZAB、etcd 都属于类 Raft 协议。

#### Paxos

理论上的经典共识算法，推导严谨，但工程实现复杂。面试只需要简单提：Paxos 是最早的分布式共识理论，Raft 是为简化 Paxos 提出的工程化版本。

### 6. 分布式存储核心思想（分片 + 多副本）

目标：横向扩展容量与吞吐，硬件故障时数据不丢失。

1. **分片 Sharding（分区）** 将数据集按照 key 哈希 / 范围切分成多个分片，不同分片存放在不同节点。 优点：负载分散，容量、吞吐横向扩展； 缺点：分片迁移会带来开销，需要分片路由。
2. **多副本 Replication** 同一份数据保存多份副本，放在不同节点。

- 目的：容错，一个节点宕机，副本接管，数据不丢失、服务不中断。
- 权衡：副本数量越高，可靠性越高；但存储开销、写放大、网络通信开销变大。

> 面试联系大模型：分布式训练里模型分片（张量并行）本质是另一种分片思想；多副本参数服务器也会用到副本冗余。

### 7. 分布式事务（了解，考的概率偏低）

ACID：原子性、一致性、隔离性、持久性。 单机数据库容易满足 ACID；分布式事务代价极高。

- 2PC 两阶段提交：准备阶段 + 提交阶段；协调者协调所有参与者。缺点：协调者单点故障，阻塞。
- 3PC 三阶段：改进 2PC，减少阻塞，但是网络分区依然有问题。 工程中很多业务会**放弃分布式事务，改用最终一致性**。

### 8. 分布式系统中的时间与时钟

- 物理时钟：机器本地硬件时钟，节点之间存在误差，不能直接用来判断事件全局顺序。
- 逻辑时钟（Lamport 时钟）：不记录真实时间，只标记事件发生的偏序关系，可以判断事件因果顺序。
- 向量时钟：可以检测两个事件是否存在因果关系，区分并发事件。

### 9. 分布式系统常见问题

1. **脑裂**：网络分区，集群分裂成两个独立子集，两边各自选出 Leader，两边同时对外提供服务，导致数据不一致。 解决：多数派机制（quorum，Raft 使用过半投票），保证任何时刻最多只有一个有效 Leader。
2. **Quorum 机制（读写过半）** 写 W、读 R，满足 W+R > N（N 副本总数），保证读到最新写入数据。
3. 消息问题：消息丢失、重复、乱序；工程常用重试 + 幂等处理。 **幂等性**：同一请求重复执行多次，结果和执行一次完全一样，防止重试带来重复写入。

### 10. 和大模型 / 算力系统关联拓展（面试官高频追问方向）

> 注意：大模型分布式训练**不是通用分布式存储**，是高性能计算集群，侧重点不一样

1. 数据并行：多 GPU 持有完整模型，不同样本输入；反向传播 AllReduce 聚合梯度。AllReduce 属于分布式集合通信，不是 Raft 这类共识。
2. 张量并行、流水线并行：模型切分在不同 GPU，属于**分布式计算**，不是分布式存储。
3. 算力集群更多关注低延迟通信（NCCL），而不是强一致存储；算力集群一般不跑 Raft 做模型参数一致性，参数同步依靠集合通信算法。

> 一句话区分：Raft/CAP 用于保证**元数据 / 控制面状态一致**；大模型多卡训练的参数同步是**数据面集合通信**，二者场景不同。


## AI系统
### 1. Transformer 基础与计算特征

Transformer 核心是多头自注意力，由大量矩阵乘法构成。

- **训练**：前向 + 反向传播，不仅要保存参数，还需要保存**激活值、梯度、优化器状态**，显存开销巨大。
- **推理**：自回归生成，prefill（输入 prompt 一次性计算）+ decoding（逐 token 串行生成）两个阶段。
    - Prefill：输入序列一次性并行计算，计算密集。
    - Decoding：一次只生成一个 token，反复计算单步注意力，**访存密集**，是推理的主要瓶颈。

### 2. 大模型训练的性能瓶颈

1. **显存容量瓶颈** 模型参数、梯度、优化器状态（如 Adam 需要保存一阶、二阶动量）、中间激活值都要驻存在 GPU 显存。模型规模大时，单卡无法放下全部数据。

> 粗略估算：FP16 训练，参数量 ×6 就是大致显存开销（参数 2B + 梯度 2B + Adam 两个动量各 2B）。

2. **显存带宽瓶颈（存储墙，本课题组核心痛点）** 矩阵运算的计算强度（计算量 / 访存量）不高，GPU 算力充足，但反复读写显存里的权重、激活，**访存带宽跟不上计算**，GPU 大量时间等待数据搬运。
3. **多卡 / 多机通信开销** 分布式训练时，多 GPU 之间交换梯度、参数。单机 NVLink 带宽高，开销小；跨机器依靠以太网 / IB 网络，通信延迟显著，成为性能瓶颈。
4. **计算开销** 超大模型的矩阵乘法总计算量巨大，需要大量 GPU 集群长时间运算。

### 3. 大模型推理的性能瓶颈

1. **自回归串行解码**：decoding 阶段逐个生成 token，无法完全并行，吞吐受限。
2. **KV Cache 开销**：每一步需要保存历史 key、value 向量。序列越长，KV Cache 占用显存越多；长序列场景下 KV Cache 是显存占用主体。
3. **低计算强度**：推理时权重反复读取，计算少，瓶颈几乎都是**显存带宽**，不是算力。
4. 批处理限制：增大 batch 可以提升吞吐，但会增加 KV Cache 占用，容易触发显存溢出。

### 4. 分布式并行三大策略（必背）

#### （1）数据并行 Data Parallelism

- 每块 GPU 保存**完整模型副本**，输入不同训练样本。
- 前向传播各自计算；反向传播算出梯度；通过 AllReduce 聚合所有 GPU 梯度，更新全局参数。
- 优点：实现简单；缺点：每卡都要存完整模型，超大模型无法使用。适合中小模型、大批量训练。

#### （2）张量并行（模型内并行，Tensor Parallelism）

- 将单个矩阵算子在维度上切分，分到多个 GPU 上并行计算。
- 例如：矩阵乘法 \(Y=XW\)，把权重矩阵 W 按列切分到不同 GPU；计算后做结果归并。
- 特点：降低单层算子对单卡显存的需求；**同一层内 GPU 之间需要频繁通信**。适合超大单一层无法放入单卡。

#### （3）流水线并行 Pipeline Parallelism

- 把模型**按层切分**，不同层放到不同 GPU，形成流水线。
- 不同 micro-batch 在流水线不同阶段并行执行。
- 存在**流水线气泡（bubble）**：当 micro-batch 数量不足时，部分 GPU 空闲，浪费算力。
- 适合层数很深的大模型，降低单卡存储压力。

> 工程中常混合使用，例如：张量并行 + 流水线并行（Megatron-LM）。

### 5. 模型层面的加速技术

1. **量化 Quantization** 降低数值精度：FP32 → FP16/BF16 → INT8 / INT4。

- 好处：权重、KV Cache 体积变小，降低访存压力、显存占用。
- 代价：引入数值误差，需要做校准，精度可能下降。

2. **剪枝 Pruning** 删除模型中不重要的权重，减少参数量，减少计算与访存。分非结构化剪枝、结构化剪枝；非结构化剪枝硬件难以加速。
3. **知识蒸馏 Knowledge Distillation** 用大模型（教师模型）输出的软标签，训练小模型（学生模型），用小模型近似大模型能力，减小体积。

### 6. 内存 / 显存系统优化（程老师课题组方向，高频追问）

1. **激活重计算（Activation Checkpointing）** 训练时不保存全部中间激活，反向时重新计算部分激活；**以计算换显存**，降低显存占用，代价是增加计算开销。
2. **异构内存 / 内存卸载** 将不常访问的冷参数、冷激活、KV Cache 迁移到 CPU 内存，热数据保留在 GPU HBM 显存；统一寻址，扩展有效容量，缓解显存不足。

> 这是程老师团队的核心研究方向之一。

3. **KV Cache 优化** KV 缓存分页、量化、复用、淘汰策略，减少长序列推理的显存占用。

### 7. 硬件架构方向的加速思路

1. **HBM 高带宽显存**：堆叠式显存，提供极高带宽，是当前 GPU 大模型训练推理主流；缺点：容量有限，成本高。
2. **存算一体 In-Memory Computing**：打破冯诺依曼架构，直接在存储阵列内部完成矩阵向量运算，消除大量数据搬运开销，适合推理场景。

### 8. 集合通信基础（NCCL）

多 GPU 之间参数 / 梯度交换常用集合通信原语：AllReduce、AllGather、ReduceScatter。

- AllReduce：所有 GPU 把数据汇总计算后，每块 GPU 都拿到全局结果，数据并行的核心原语。

> 区分：集合通信是算力集群做参数同步，和 Raft 这类元数据共识协议不是一回事。

### 9. 常见框架基础（了解即可）

PyTorch、TensorFlow；Megatron-LM 是经典大模型并行训练框架，实现混合并行。
